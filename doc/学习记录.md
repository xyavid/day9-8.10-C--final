## 三、can协议帧结构
| 字段 | 长度 | 作用 |
|---|---:|---|
| SOF 帧起始 | 1 bit | 标志一帧开始，为显性位 |
| 标识符 Identifier | 11 bit | 表示消息类型和节点地址，也用于总线仲裁 |
| RTR | 1 bit | 数据帧为显性位，远程帧为隐性位 |
| IDE | 1 bit | 标准帧为显性位，表示使用 11 位 ID |
| 保留位 r0 | 1 bit | 保留，通常为显性位 |
| DLC | 4 bit | 表示数据长度，经典 CAN 范围为 0~8 字节 |
| Data 数据段 | 0~8 字节 | 存放实际控制数据 |
| CRC 序列 | 15 bit | 对前面的帧内容进行 CRC 校验 |
| CRC 分隔符 | 1 bit | 固定为隐性位 |
| ACK 槽 | 1 bit | 接收节点正确收到数据后发送显性位 |
| ACK 分隔符 | 1 bit | 固定为隐性位 |
| EOF 帧结束 | 7 bit | 标志当前帧结束 |  
- can的crc与本作业校验和的区别：  
本作业的校验和为checksum = (header[0] + header[1] + cmd) 的低 8 位;  
而can的crc-15经查询则是x^15 + x^14 + x^10 + x^8 + x^7 + x^4 + x^3 + 1
相同点：主要是都确保了基本的校验和作用，通过校验保证数据完整性  
不同点：

| 对比项 | 本作业校验和 | CAN CRC |
|---|---|---|
| 计算方式 | 多个字节直接相加 | 基于多项式除法计算 |
| 校验长度 | 8 bit | 15 bit CRC |
| 检错能力 | 较弱 | 较强，能检测更多随机错误和突发错误 |
| 校验对象 | 头部字节和命令字 | CAN 帧中的位流 |
| 实现方式 | 由应用程序手动计算 | 通常由 CAN 控制器硬件自动完成 |
| 其他保护 | 只有校验和 | 还具有位监视、位填充、格式和 ACK 检查 |
| 错误处理 | 程序自行丢弃错误包 | CAN 控制器可发送错误帧并自动重发 |

- 自行设计的话，确实没有什么思路，对于can的了解比较浅，id设计就是消息的优先级、本身类型、编号等等，对电机更是没有什么概念，数据段应该存储电机的加速度，扭矩，位置，转速之类的，只能枚举一点电机的参数
